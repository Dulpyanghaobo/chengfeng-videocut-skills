# 汽车科技视频精剪

本 Skill 的真实文件路径向上两级是工具包根目录。安装入口可能是符号链接，先解析真实路径；命令中的 `<工具包>` 使用这个绝对路径。所有素材、项目和渲染均由本工具包管理，无需加载旧版“剪口播”或 chengfeng 的更新流程。

## 输入与范围

- 必需：真实粗剪视频。主题、车型在音频里明确时自行提取；不明确且会影响素材选择时集中询问。
- 可选：同期口播稿、与当前粗剪同步的 SRT、官方资料、已有素材。以实际音频为准，稿件帮助理解和纠字，不改录好的话。
- 默认沿用母版比例、帧率、顺序、停顿、时长与声音。新增画面覆盖主轨；独立片头、延时或重剪须来自当前明确要求。
- 按已保存的视觉偏好工作。动画只用二维 SVG / Remotion，保留连续动作，避免静态卡片推拉与逐条堆字。车型外观优先真实素材；通用结构示意不能声称是特定车型实物。

## 执行

1. `node "<工具包>/bin/auto-video.mjs" doctor`。定位现有项目后复用；新建时：
   ```sh
   node "<工具包>/bin/auto-video.mjs" init --video "<粗剪视频>" --srt "<同步字幕>" --out "<项目目录>"
   ```
   无 SRT 时省略；已获准的云端转录可用 `transcribe "<project.json>"`。没有凭证时说明缺少什么，继续不依赖字幕的素材整理；不调用本地 ASR 或编造时间。
2. 校对字幕的专名、数字、单位与分屏。真实技术主张有疑问时检索原始资料，单独报告，不用字幕静默替换口播事实。读 [时间线与项目合同](../../references/project-contract.md)。
3. 按语义生成画面需求。读取 [汽车素材搜集](../../references/asset-sourcing.md)，先检索指定素材和本地库，再补充外部真实素材。只有实际取得并核对过的文件才能入镜。
4. 每个镜头明确表达任务：观点/问题可留真人；车型展示用对应素材；机制用二维场景；参数引用保留证据。可直接运行 `search`、`list`，从固定组件选择，不必每次重画。读取 [组件与参数](../../references/components.md) 后写 `project.json` 的 `clips`。镜头长短跟语义与运动匹配。
5. `validate --project "<project.json>"` → `prepare "<project.json>"` → `render "<project.json>" --out "<整片预览.mp4>"`。这是用户要求完成剪辑时已授权的本地交付，不额外逐镜头索取确认。先执行一次代表片段验证新风格，已有确定风格可直接整片预览。技能并不代表未经检查的自动出片算法；需要 Agent 实际选择素材和编排。
6. 用 `inspect-render "<project.json>" --video "<实际输出.mp4>"` 生成实际导出的关键帧、边界帧与联系表；真正打开这些图检查主体裁切、车型、字幕、层次、边界与动画推进。技术检查、实际像素检查、人工听音分别记录；没人听过写 UNVERIFIED。音效在画面确定后最后处理，`soundEffects` 是预留清单，当前合成器保留母版声音、覆盖素材静音，不宣称已添加音效。

## 修改与交付

按片段 ID 修改，保留其他片段和母版。项目的 `assets.lock.json` 锁定版本；普通重渲染不得刷新素材锁。替换公共库素材不改变旧项目快照。覆盖已有输出使用用户要求的新路径，或在授权覆盖时加 `--overwrite`。

交付整片预览/成片、项目路径和确有缺口的列表。用户指定素材独立交付时按当次要求执行，不把一次项目的交付方式固化成全局偏好。
